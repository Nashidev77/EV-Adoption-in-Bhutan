# 🔌 Electric Vehicle Adoption in Bhutan

A beginner data science project built with **Streamlit** and **scikit-learn**.
It explores which household factors might relate to interest in switching to an
electric vehicle in Bhutan, using a small machine learning model.

**Live app:** https://ev-adoption-in-bhutan.streamlit.app/
**Author:** Avinash Biswa

---

## ⚠️ The data in this app is invented

Every row was generated by a formula written for this project. No survey was
carried out, and no real household, person or vehicle is represented. The app
demonstrates a machine learning workflow; it does **not** describe what
Bhutanese households actually intend to do, and it must not be used for policy,
business or purchasing decisions.

---

## Why this topic

Bhutan produces most of its electricity from hydropower, but imports every litre
of fuel it burns. That makes electric vehicles an unusual case here: the "fuel"
is already domestic, while steep terrain, long drives between dzongkhags and the
purchase price all push the other way. This project turns that tension into a
simple prediction question:

> Given what we know about a household, is it likely to switch to an electric
> vehicle within the next two years?

## What the app does

The app has four tabs:

| Tab | What it shows |
|---|---|
| **Overview** | The question, how the fictional data was built, and the limits of the project |
| **Explore data** | Distribution and comparison charts for any feature, group averages, and the records table |
| **Prediction demo** | Set the details of one fictional household and get a prediction with a probability |
| **Model results** | Accuracy, ROC-AUC, precision, recall, F1, a confusion matrix, a classification report, and the model's feature weights |

---

## The dataset

800 fictional households, generated with a fixed random seed (42) so the results
are identical every time the app runs.

**Numeric features**

| Feature | Range |
|---|---|
| Age of main driver | 22–65 |
| Daily commute | 1–90 km |
| Age of current vehicle | 0–20 years |
| Monthly fuel cost | Nu 600–18,000 |
| Reliable electricity | 16–24 hours/day |

**Category features**

| Feature | Values |
|---|---|
| Dzongkhag | Thimphu, Paro, Chhukha, Punakha, Wangdue Phodrang, Bumthang, Trashigang, Samtse |
| Area type | Urban, Semi-urban, Rural |
| Household income band | Below Nu 20,000 → Above Nu 70,000 |
| Charging access | Home charging possible, Public station nearby, No reliable access |
| Terrain | Flat valley, Hilly, Steep mountain |
| Knows about the EV subsidy | Yes / No |
| Owns a second vehicle | Yes / No |

**Target:** `ev_adoption` — *Likely to adopt* (320 households, 40%) or
*Not likely yet* (480 households, 60%).

Each household is given a score from a weighted rule, random noise is added, and
the top 40% of scores are labelled *Likely to adopt*. About 2% of the values in
four columns are then deleted, so the pipeline has to handle missing data the way
a real dataset would.

---

## Method

1. **Split** — 80% training, 20% testing, stratified on the target
2. **Numeric columns** — fill gaps with the median, then standardise
3. **Category columns** — fill gaps with the most frequent value, then one-hot encode
4. **Model** — logistic regression (`max_iter=1000`)
5. **Evaluate** — score on the 160 test households the model never saw

---

## Results

Measured on the held-out test set:

| Metric | Score |
|---|---|
| Accuracy | 0.794 |
| ROC-AUC | 0.847 |
| Precision | 0.792 |
| Recall | 0.656 |
| F1-score | 0.718 |

The strongest positive weights were home charging access, living in Thimphu, a
high monthly fuel bill and an ageing current vehicle. A long daily commute pushed
hardest in the other direction, which matches the range-anxiety assumption built
into the data.

Recall (0.656) is noticeably lower than precision (0.792): when the model flags a
household as a likely adopter it is usually right, but it misses about a third of
them. On a real project that trade-off would be worth tuning, because missing
potential adopters and wrongly targeting non-adopters have different costs.

## Limitations

- **The data is invented.** The model can only rediscover the rule used to create
  it. A good score shows the pipeline works end to end; it says nothing about
  whether the rule matches reality.
- **One split, one model.** The scores come from a single 80/20 split of one
  logistic regression. Cross-validation and a comparison against other algorithms
  would give a much more honest picture.
- **Real data would be messier.** A genuine survey would bring uneven response
  rates, self-reporting bias and far more missing data than the 2% added here.

To take this further, the obvious next step is a small real survey of vehicle
owners in one dzongkhag, and then re-running this same pipeline on that data.
